# Модульный конструктор договоров (LegalTech · ANTEI × ИТМО)

Блочное редактирование контрактов с ИИ и стресс-тестированием рисков.
**Студент:** Новиков Тимофей Витальевич (Индустриальный трек, тендерные контракты).

Текущий прототип выполняет анализ текста, смысловое разбиение и проверку связей. Редактирование версий, генерация договоров и экспорт DOCX/PDF относятся к дальнейшему годовому объёму.

Развёрнутое демо: https://legaltech-contract-lab.bestmaxim1.chatgpt.site — фиксированные авторские примеры, без пользовательских документов и API-ключей. Доступно по ссылке без входа; публичный доступ согласован владельцем. Полный живой анализатор находится в этом репозитории.

## Состав репозитория (Этап 1 · Неделя 1)

- `llm_layer.py` — единый слой вызова моделей Google AI Studio (REST API `v1beta`), поддерживающий смену модели через переменную окружения `LLM_MODEL`, автоматические ретраи при `429 / 500 / 503` и проверку системных сертификатов SSL.
- `run_models_test.py` — скрипт экспериментальной проверки 6 моделей (`gemini-2.5-flash`, `gemini-3.8-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-pro-preview`, `gemma-4-31b-it`, `gemma-4-26b-a4b-it`) на задачах модульной декомпозиции договора (`decompose`) и анализа рисков по ФЗ-152 (`risk_152fz`).
- `results/models_test.json` — сырые результаты и тайминги прогона 12 запросов.
- `results/sample_contracts_ru.json` — стартовый набор из 5 русскоязычных стресс-примеров (ПДн, Terms of Use, Политика конфиденциальности, Договор оказания услуг) с заложенными уязвимостями, ссылками на статьи ФЗ-152 / ГК РФ / ст. 13.11 КоАП РФ и безопасными редакциями.
- `report_week1.html` — автономный интерактивный HTML-отчёт по итогам Недели 1.

## Быстрый запуск

### Приложение второго этапа (локальная первая версия)

Python 3.10+, Node.js 22.18+ или 24.12+. Из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
test -f .env || cp .env.example .env
cd frontend
npm ci
npm run build
cd ..
./start-local.command
```

Откройте http://127.0.0.1:8000 и оставьте окно запуска открытым. На Mac можно дважды нажать `start-local.command` после установки. Если порт уже занят, приложение, возможно, уже работает. Это локальный адрес текущего компьютера, не опубликованное демо.

В `.env` задайте `ROUTER_API_KEY`, необязательно `GEMINI_API_KEY` для резервного провайдера. Не перезаписывайте существующий `.env` шаблоном. Ключи не передаются браузеру. API Router: отправка job и опрос каждые 10 секунд, общий таймаут 300 секунд (настраивается `LLM_TIMEOUT_SECONDS`). При таймауте удалённая задача может продолжить работу; автоматической повторной отправки нет. В экспериментах отключена автоматическая подмена модели (`fallback: false`). Провайдер выбирается в интерфейсе; на Google автоматически не переключаемся, чтобы сохранить воспроизводимость.

Вставьте публичный/синтетический текст или загрузите UTF-8 `.txt` (до 120000 символов). Приложение выделяет исходные фрагменты с точными смещениями, отдельным вызовом модели объединяет их по смыслу и затем анализирует риски. Код проверяет сплошное покрытие, порядок и отсутствие повторов. Ответ проверяется по JSON-схеме, цитаты сверяются с оригиналом. При артефактах PDF допускаются только различия в пробелах и только однозначное совпадение; в результат возвращается дословный оригинал и его смещения. Каждый результат хранится в локальной SQLite (`data/runtime/`, вне Git), экспортируется в JSON. Последний анализ можно восстановить после обновления страницы в том же браузере. Полные PDF/DOCX в интерфейсе пока не поддерживаются; загружать сканы бессмысленно.

Файлы второй версии: `model_client.py` (Router/Google), `pipeline.py` (блоки, промпты, проверка доказательств), `app.py` (FastAPI/очередь/SQLite), `frontend/` (Vue), `tests/` (проверки без расхода API).

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python collect_corpus.py
.venv/bin/python evaluate.py --limit 6
.venv/bin/python generate_report.py
```

Коллектор проверяет оба файла и их SHA-256, восстанавливает отсутствующие/повреждённые снимки. Новую версию источника сохраняет отдельно, не подменяя зафиксированную. Для повторения неудачных загрузок используйте `--retry-failed`. Дата, хеши и ошибки — в `data/corpus/manifest.json`. Полные публичные документы остаются локально в `raw/`, права у издателей. Эксперимент — 12 реальных запросов (2 промпта × 6 синтетических dev-примеров), он расходует лимиты Router. Результаты и ошибки сохраняются в `results/prompt_comparison.json`, повторный запуск перезаписывает файл: для нового прогона используйте `--output results/another-run.json`. Разметка авторская, не юридическая экспертиза. `requirements.lock.txt` фиксирует проверенное окружение; npm-зависимости фиксированы `frontend/package-lock.json`.

HTML-черновик создаётся только локально. Репозиторий, демо и отчёт автоматически никуда не публикуются и не отправляются.

Ограничения: связи проверяются отдельным проходом, для длинного документа — до четырёх выбранных пар; полнота не доказана. Нет нормативного поиска и экспертной валидации; смысловые группы выбирает модель, проверка границ пока только на грубой авторской разметке. Генерация/редактор договоров и DOCX/PDF-экспорт относятся к дальнейшим этапам. Развёрнутое демо показывает фиксированные примеры. Многопользовательский живой анализ потребует полноценной аутентификации, квот и отдельного хранилища; текущий сервер запускается только на loopback одним worker.

### Проверка на реальных фрагментах

`data/evaluation/pair_specs.json` фиксирует SHA-256 снимка, границы исходного фрагмента и одну внесённую правку. `build_benchmark.py` не меняет оригинал, останавливается при изменении хеша и сохраняет обе версии пары в одном семействе и разбиении. Полные производные тексты находятся в `data/corpus/derived/` вне Git. Эти три пары — dev-пилот с авторскими, не экспертными метками, а не финальный тест.

```bash
.venv/bin/python build_benchmark.py
.venv/bin/python evaluate_pairs.py --output results/new-pilot.json --timeout 120
.venv/bin/python analyze_file.py data/corpus/raw/sbertech_consent.txt --doc-type consent --input-origin pdf_extracted --output results/private/new-semantic-run.json
```

Первый парный прогон сохранён в `results/real-derived-pilot-v1.json`. Порядок двух промптов чередуется; у обоих одинаковые абзацные блоки, чтобы сравнивать именно риск-промпт. Разметка касается только указанной категории; другие категории нельзя объявлять ложными срабатываниями. Ошибки API учитываются отдельно и снижают показатель «правильно / все случаи». Сырые ответы и цитаты хранятся в `results/private/` вне Git. Сохранены параметры, версии и SHA-256 кода на момент прогона; последующие изменения кода не переписывают историю.

`analyze_file.py` проверяет полный пайплайн со смысловым группированием. Результат сохраняется только при успешной валидации. Совпадение всех символов без пробелов и восстановление оригинальной цитаты не подтверждают правильность объяснения модели — юридическая проверка остаётся отдельной задачей.

### Исправления по независимому аудиту

История API привязана к HttpOnly-сессии браузера: другой клиент не получает анализ по известному ID. SQLite имеет права 0600, каталог — 0700. Локальные результаты хранятся до удаления (`DELETE /api/analyses/{id}`); автоматический срок удаления пока не включён. Используйте только открытые/синтетические документы. Новая сессия не получает доступ к старым результатам; это локальная сессия, не полноценная учётная запись. Результаты до введения владельцев сохранены в базе, но через API недоступны.

API возвращает неизменяемый снимок ввода. Изменение текста, типа, модели или провайдера скрывает прежний разбор. UTF-8 декодируется строго. Тело HTTP-запроса ограничено 1 МБ по фактически прочитанным байтам, лишние поля запрещены. Аутентифицированные вызовы моделей не следуют HTTP-редиректам, удалённые тела ошибок не попадают в журналы.

ID задачи Router и полученные ответы сохраняются сразу в приватной SQLite. После сетевого сбоя интерфейс продолжает GET того же анализа. Кнопка «Возобновить тот же анализ» использует сохранённые вызовы (`POST /api/analyses/{id}/resume`), включая после перезапуска приложения. Окно сбоя между принятием POST провайдером и записью ID на диск остаётся; серверной идемпотентности Router не документирует. Прямой Google API не поддерживает такое восстановление незавершённого вызова.

Повторяющиеся цитаты, обрывы слов/чисел и пустые объяснения отклоняются. Эквивалентные пробелы между словами восстанавливаются без изменения оригинала; склейка артефактов внутри слова разрешена только для явно отмеченного `pdf_extracted` (`analyze_file.py --input-origin pdf_extracted`). Связь проверяется по двум непересекающимся цитатам; они могут относиться к одному смысловому блоку. Оговорка не объявляется автоматически ошибкой договора. Все замечания имеют `review_status=unreviewed`.

### Проверка полного конвейера

```bash
.venv/bin/python prepare_e2e_cases.py
```

Это фиксированный протокол на шести составных примерах двух отложенных семейств (Selectel, 2ГИС), без пересечения с семействами первого dev-пилота. Добавлены три абзацных запуска на внесённых рисках и одна попытка Gemma. Результаты в `results/e2e-heldout-v1.json`, сырые ответы вне Git. Скрипт не перезаписывает существующий прогон. Эксперимент расходует API-лимиты, ожидаемый бюджет до 27 запросов. Результат небольшого набора не доказывает юридическую точность и превосходство модели.
